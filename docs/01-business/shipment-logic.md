# منطق موديول الشحنات والتصدير — Nilotic Frost ERP

## نظرة عامة

موديول الشحنات هو **قلب النظام** — يربط كل الموديولات الأخرى في معاملة واحدة متكاملة تنتهي بإيراد مالي ومخزون مخصوم وتتبع كامل.

---

## سير عمل الشحنة الكامل

```
طلبية عميل (ORD) 
    ↓
اختيار باتشات من مخزون الجاهز
    ↓
احتساب التكلفة الكاملة
    ↓
اعتماد الشحنة (SHP) ← يشغّل تلقائياً:
    ├── خصم رصيد الباتشات المخصصة
    ├── تحديث حالة الطلبية (مكتملة / جزئية)
    └── إنشاء قيد AR للعميل (فاتورة تصدير)
```

## شاشة تنفيذ الشحنة (shipment-create.html)

### الخطوات الثلاث الرئيسية (كما في الكود)

**الخطوة 1: اختيار طلبية العميل**
- اختيار اسم العميل → يُعبأ تلقائياً بطلبياته المفتوحة
- اختيار رقم الطلبية → يُعبأ: المنتج، الكمية المتبقية، السعر المتفق، شروط التسليم، سعر الصرف
- الحقول المستدعاة آلياً (محمية من التعديل): `badge-derived`

**الخطوة 2: تخصيص لوطات من المخزون**
- اختيار باتشات من `finishedGoodsBatches`
- تحديد كمية من كل باتش
- النظام يحسب `totalProdCost` كمجموع `qty × costPerKg` لكل باتش
- يُعرض شجرة الموردين لكل باتش مختار (DNA traceability)
- التحقق: `allocQty ≤ fg.availableQty` → خطأ إذا تجاوز

**الخطوة 3: التحقق المالي**
- عرض الإيراد الإجمالي: `شحن كجم × سعر EUR × سعر صرف`
- عرض التكاليف الإضافية (شحن بري، بحري، جمارك، شهادات، ميناء)
- احتساب صافي الربح والهامش

---

## معادلات الربحية

### الإيراد
```
الإيراد الإجمالي (EGP) = الكمية المشحونة (كجم) × سعر البيع (EUR) × سعر الصرف
```
مثال: `4000 × 1.85 × 53.20 = 393,680 ج.م`

### التكلفة الكاملة للشحنة

```javascript
costs = {
  productionCost: totalProdCost,       // تكلفة الإنتاج (من الباتشات)
  inlandTrucking: 6500,                // شحن بري للميناء
  oceanFreight: 22000,                 // شحن بحري
  customsClearance: 4500,              // تخليص جمركي
  inspectionCertificates: 2500,        // شهادات فحص وصحة
  portTerminalCharges: 3500            // رسوم الميناء
}
totalShipmentCost = sum(all costs)
```

### الربح
```
صافي الربح (EGP) = الإيراد الإجمالي - إجمالي التكلفة
هامش الربح % = (صافي الربح ÷ الإيراد الإجمالي) × 100
```
مثال: `(228,440 ÷ 393,680) × 100 = 58%`

## حالات الطلبية (Order Status)

| الحالة | متى تحدث |
|-------|---------|
| `جديدة` | عند إنشاء الطلبية |
| `قيد التجهيز والتخصيص` | عند بدء تجهيز الشحنة |
| `مشحونة جزئياً` | عند شحن جزء من الكمية المطلوبة |
| `مكتملة بالكامل` | عند شحن الكمية بالكامل (`unfulfilledQtyKg === 0`) |

---

## الشحن الجزئي (Partial Fulfillment)

النظام يدعم شحن طلبية على دفعات:
```javascript
order.unfulfilledQtyKg = Math.max(0, order.unfulfilledQtyKg - shippedQty);
order.status = order.unfulfilledQtyKg === 0 ? "مكتملة بالكامل" : "مشحونة جزئياً";
```

---

## التدقيق (Audit Trail)

كل شحنة تحتوي على سجل `audit` يُسجّل:
- الوقت والتاريخ
- المستخدم الذي نفّذ
- الإجراء (`DISPATCH`)
- الملخص النصي

---

## التحقق من البيانات (Validations)

| التحقق | الرسالة عند الخطأ |
|-------|-----------------|
| الطلبية موجودة | "لم يتم العثور على طلبية العميل المحددة" |
| الكمية ≤ الرصيد المتبقي في الطلبية | "كمية الشحنة تتجاوز الرصيد المتبقي بالطلبية!" |
| الكمية من الباتش ≤ المتاح | "الكمية المخصصة من الباتش تتجاوز الرصيد المتاح!" |

---

## الآثار التلقائية للشحنة

عند اعتماد الشحنة تحدث هذه التغييرات تلقائياً:
1. `fg.availableQty -= allocQty` لكل باتش مخصص
2. `order.unfulfilledQtyKg -= shippedQty`
3. `order.status` يتحدث تلقائياً
4. إنشاء قيد `TXN` جديد (AR) في `financialTransactions`

## سجل الشحنات (Shipment Registry — shipments.html)

يعرض:
- جدول بكل الشحنات مع الفلترة حسب: العميل، المنتج، الحالة، التاريخ
- عمود ربح الشحنة وهامشها مباشرة في الجدول
- رابط لصفحة تفاصيل الشحنة `shipment-details.html`

## صفحة تفاصيل الشحنة (shipment-details.html)

تعرض 6 أقسام:
1. **نظرة عامة:** بيانات الحاوية والعميل والتواريخ
2. **بيانات الإنتاج:** الباتشات المخصصة وتكلفة الكيلو
3. **بيانات المخزون:** اللوطات الخام المصدر
4. **تفاصيل التكلفة:** تفصيل كل بند تكلفة
5. **ملخص الربح:** إيراد، تكلفة، ربح، هامش
6. **شجرة التتبع:** من المزرعة ← اللوط ← الإنتاج ← الباتش ← الشحنة ← العميل
