# القواعد البيزنسية الرابطة بين الموديولات — Nilotic Frost ERP

## نظرة عامة

هذا الملف يوثّق القواعد التي تعبر حدود موديول واحد وتؤثر على أكثر من كيان في آن واحد.

---

## 1. قاعدة التعبئة التلقائية عبر الاتفاقيات

**الموديولات:** العملاء ←→ الشحنات

### الآلية

عند اختيار العميل في شاشة إنشاء الشحنة:
- يُستدعى `customer.agreedProducts` المرتبط بهذا العميل
- يُعبأ تلقائياً: سعر البيع بالعملة الأجنبية، مواصفات التعبئة، المنتجات المتاحة

### مثال

```
العميل: شركة سما (هولندا)
        ↓
agreedProducts = [
  { productName: "فراولة مجمدة IQF", targetPriceEur: 1.85, packagingSpec: "كرتونة 10 كجم" },
  { productName: "مانجو مكعبات",      targetPriceEur: 2.40, packagingSpec: "كرتونة 10 كجم" }
]
        ↓
في الشحنة: سعر البيع = 1.85 EUR (محمي من التعديل العشوائي)
```

## 2. قاعدة توريث أسعار المقاول من المحطة

**الموديولات:** المحطات ←→ المقاولون ←→ الإنتاج

### الآلية

عند اختيار المحطة في عملية الإنتاج:
```javascript
const contractor = state.contractors.find(c => c.station === selectedStation);
const contractorRate = contractor ? contractor.tariffRatePerKg : 2.00;
```

- يُستدعى المقاول الافتراضي المرتبط بالمحطة
- يُعبأ سعره بالكيلو تلقائياً
- يمكن تجاوزه يدوياً

## 3. قاعدة التكلفة الموزونة عند دمج اللوطات

**الموديولات:** الخام ←→ الإنتاج ←→ الجاهز

### الآلية

عند استخدام أكثر من لوط في عملية إنتاج واحدة، تُحسَب تكلفة الكيلو بالمتوسط الموزون:
```
التكلفة الإجمالية = Σ (كمية اللوط × سعر كيلو اللوط)
تكلفة الكيلو الموزونة = إجمالي التكلفة ÷ إجمالي الكمية
```

هذه القيمة تنتقل للباتش الجاهز وتُستخدم في احتساب ربح الشحنة.

### مثال

```
LOT-RAW-001: 4000 كجم × 18.50 = 74,000 ج.م
LOT-RAW-002: 2000 كجم × 19.20 = 38,400 ج.م
                                ═══════
الإجمالي:   6000 كجم          112,400 ج.م
المتوسط:    112,400 ÷ 6000 = 18.73 ج.م/كجم (في جانب الخام)
```

## 4. قاعدة الربط التلقائي: عملية → قيد مالي

**الموديولات:** جميع العمليات ←→ الماليات

### الجدول الشامل

| الحدث | القيد المالي التلقائي |
|------|---------------------|
| تسجيل لوط خام | AP للمورد بقيمة `netQty × unitCost + transportCost` |
| شراء مستلزمات | AP لمورد المستلزمات بقيمة `qty × unitPrice` |
| شراء صفقة جاهزة | AP للمورد بقيمة `qtyKg × purchasePricePerKg + transportCost` |
| اعتماد إنتاج | AP للمقاول بقيمة `finishedOutputKg × contractorRate` |
| اعتماد شحنة | AR للعميل بقيمة `shippedQtyKg × sellingPriceEur × fxRate` |

## 5. قاعدة تتبع DNA المورد عبر الباتش

**الموديولات:** المورد ←→ الخام ←→ الإنتاج ←→ الجاهز ←→ الشحنة

### الآلية

عند الإنتاج، تُبنى شجرة `suppliersSummary` في الباتش الجاهز:

```javascript
// لكل لوط مسحوب، يُضاف المورد لـ suppliersSummaryMap
suppliersSummaryMap[supplierName] += qty;

// تحويل لنسبة مئوية
suppliersSummary = Object.keys(suppliersSummaryMap).map(sName => ({
  supplierName: sName,
  sharePct: (suppliersSummaryMap[sName] / totalRawKg) * 100
}));
```

### مثال

```
باتش: FG-PR-2026-001
المصادر:
  - مزارع الوادي: 4000/6000 = 66.7%
  - شركة الخير:   2000/6000 = 33.3%
```

هذه المعلومة متاحة في:
- تفاصيل الباتش
- تفاصيل الشحنة (Traceability Tree)
- تقرير الموردين

## 6. قاعدة الإيفاء الجزئي للطلبيات

**الموديولات:** طلبيات العملاء ←→ الشحنات

### الآلية

```javascript
// عند كل شحنة:
order.unfulfilledQtyKg -= shippedQty;
order.status = order.unfulfilledQtyKg === 0 ? "مكتملة بالكامل" : "مشحونة جزئياً";
```

**قواعد التحقق:**
- `shippedQty ≤ order.unfulfilledQtyKg` — لا يمكن الشحن أكثر من الباقي
- يمكن إنشاء أكثر من شحنة لنفس الطلبية

---

## 7. قاعدة التحقق من الرصيد عند الشحن

**الموديولات:** الشحنات ←→ مخزون الجاهز

### الآلية

```javascript
// لكل باتش مخصص في الشحنة:
if (allocQty > fg.availableQty) {
  throw new Error("الكمية المخصصة تتجاوز الرصيد المتاح!");
}
fg.availableQty -= allocQty;
```

---

## 8. قاعدة سعر الكيلو الموروث للشحنة (FIFO-like)

**الموديولات:** الإنتاج ←→ الجاهز ←→ الشحنات

### الآلية

الشحنة ترث تكلفة الكيلو مباشرة من الباتشات المخصصة:
```javascript
totalProdCost = Σ (allocQty × fg.costPerKg) لكل باتش
```

لا يوجد إعادة حساب — التكلفة مجمدة في الباتش عند إنشائه.

---

## 9. قاعدة سعر الصرف الثابت في الطلبية

**الموديولات:** العملاء ←→ الطلبيات ←→ الشحنات

### الآلية

سعر الصرف `fxRate` يُحدَّد عند إنشاء الطلبية ويُثبَّت:
```javascript
// في addClientOrder:
fxRate: parseFloat(orderData.fxRate) || 53.20
// في createShipment:
const fxRate = order.fxRate || 53.20;
```

> **ملاحظة:** لا يوجد تعديل تلقائي لسعر الصرف عند تغير السوق بعد إنشاء الطلبية. يجب تسجيل طلبية جديدة بسعر صرف محدّث.

---

## 10. قاعدة التحصيل/السداد وتحديث رصيد الحساب

**الموديولات:** الماليات ←→ الخزينة

### الآلية

عند تسجيل حركة مالية يدوية:
```javascript
isCollection = type.includes("تحصيل") || type.includes("Inflow");
if (isCollection) { account.balance += amount; }
else              { account.balance -= amount; }
```

> الرصيد يتحدث فوراً دون أي قيود أمان — لا يُمنع الرصيد السالب في الخزينة.
