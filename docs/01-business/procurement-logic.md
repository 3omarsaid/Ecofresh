# منطق موديول الشراء والمشتريات — Nilotic Frost ERP

## نظرة عامة

الشراء في النظام ينقسم إلى ثلاثة أنواع رئيسية:
1. **شراء المواد الخام** (Raw Material Procurement)
2. **شراء المستلزمات والكراتين** (Packaging Procurement)
3. **شراء بضاعة جاهزة** (Direct Finished Goods Purchase)

---

## أولاً: شراء المواد الخام

### الدالة المسؤولة: `ERPState.addRawMaterialArrival(arrivalData)`

### حقول النموذج المطلوبة

| الحقل | الوصف | إلزامي؟ |
|-------|-------|--------|
| `station` | المحطة المستلِمة | ✅ |
| `rawProduct` | نوع الخام (فراولة/مانجو/بامية) | ✅ |
| `supplierName` | اسم المورد | ✅ |
| `grossQty` | الوزن الإجمالي (كجم) | ✅ |
| `tareQty` | وزن المركبة فارغة | اختياري |
| `netQty` | صافي الوزن = gross - tare | محسوب تلقائياً |
| `unitPrice` | سعر الكيلو (ج.م) | ✅ |
| `transportCost` | تكلفة النقل | اختياري |
| `brixDegree` | درجة البريكس (فحص جودة) | اختياري |
| `truckPlate` | لوحة السيارة | اختياري |
| `date` | تاريخ الاستلام | ✅ |

### معادلة تكلفة اللوط

```
صافي الكمية (كجم) = الوزن الإجمالي - وزن المركبة
إجمالي تكلفة الخام = (صافي الكمية × سعر الكيلو) + تكلفة النقل
تكلفة الكيلو الموزونة = إجمالي التكلفة ÷ صافي الكمية
```

**مثال:**
```
5000 كجم × 18.50 ج.م + 1500 ج.م نقل = 94,000 ج.م
تكلفة الكيلو = 94,000 ÷ 5000 = 18.80 ج.م/كجم
```

### الآثار التلقائية عند التسجيل

1. **إنشاء لوط جديد** في `state.rawBatches` بـ `availableQty = netQty`
2. **إنشاء قيد مالي AP** تلقائياً:
   ```
   TXN = "استحقاق توريد خام (AP)" بقيمة إجمالي التكلفة
   ```
3. **إنشاء رقم اللوط** تلقائياً: `LOT-RAW-YYYYMMDD-NN`

### رقم اللوط (Batch ID) — قاعدة التسمية

```
LOT-RAW-{YYYYMMDD}-{NN}
مثال: LOT-RAW-20260815-01
```

## ثانياً: شراء المستلزمات والكراتين

### الدالة المسؤولة: `ERPState.addPackagingPurchase(purchaseData)`

### حقول النموذج

| الحقل | الوصف |
|-------|-------|
| `supplyId` | معرّف المستلزم (إذا موجود) |
| `name` | اسم المستلزم |
| `category` | كرتونة / أكياس / بالتات / لاصق / تغليف |
| `qty` | الكمية |
| `unitPrice` | سعر الوحدة |
| `supplierName` | مورد المستلزمات |
| `invoiceNo` | رقم الفاتورة |
| `capacityKg` | سعة الكرتونة بالكجم (للكراتين) |

### الآثار التلقائية

1. **إذا المستلزم موجود مسبقاً:** `item.stock += qty`
2. **إذا المستلزم جديد:** يُضاف سجل جديد لقائمة `supplies`
3. **قيد مالي AP:** `"استحقاق توريد مستلزمات (AP)"`

## ثالثاً: شراء بضاعة جاهزة (صفقات)

### الدالة المسؤولة: `ERPState.addDirectPurchaseDeal(deal)`

### الفرق عن شراء الخام

| الخاصية | شراء خام | شراء جاهز |
|---------|---------|----------|
| يمر بعملية إنتاج؟ | ✅ نعم | ❌ لا |
| يُنشأ لوط خام؟ | ✅ نعم | ❌ لا |
| يُنشأ باتش جاهز مباشرة؟ | ❌ لا | ✅ نعم |
| نوع الباتش | `FG-PR-XXXX` | `FG-DIR-XXXX` |
| مورده | مزارع خام | مصنع/مورد جاهز |

### حقول الصفقة

| الحقل | الوصف |
|-------|-------|
| `supplierName` | مورد البضاعة الجاهزة |
| `productName` | اسم المنتج |
| `station` | محطة الاستلام |
| `qtyKg` | الكمية (كجم) |
| `packageType` | نوع التعبئة (كرتونة 10 كجم) |
| `packageCount` | عدد الكراتين |
| `purchasePricePerKg` | سعر الكيلو |
| `transportCost` | مصاريف النقل |
| `productionDate` | تاريخ الإنتاج |
| `expiryDate` | تاريخ الصلاحية |
| `invoiceNo` | رقم الفاتورة |
| `qualityStatus` | حالة الجودة |

### معادلة تكلفة الصفقة

```
إجمالي الشراء = الكمية × سعر الكيلو
التكلفة الكاملة = إجمالي الشراء + مصاريف النقل
تكلفة الكيلو = التكلفة الكاملة ÷ الكمية
```

## سجل المشتريات في الواجهة

### شاشة وارد الخام (raw-purchases.html)

- جدول بكل لوطات الخام المستلَمة
- كل سطر: رقم اللوط، المورد، المحطة، الكمية الأولية، المتبقي، التكلفة، الحالة
- فلترة حسب المورد والمحطة والمنتج

### شاشة وارد المستلزمات (packaging-purchases.html)

- جدول بكل عمليات شراء المستلزمات
- عرض رصيد كل مستلزم بعد الشراء

### شاشة وارد الجاهز (finished-purchases.html)

- جدول الصفقات مع: رقم الصفقة، المورد، المنتج، الكمية، التكلفة، الباتش المُنشأ

## التحقق من صحة البيانات (Validations)

| التحقق | السلوك في الكود |
|-------|--------------|
| الكمية المطلوبة للإنتاج > الرصيد المتاح | `Math.max(0, availableQty - usedQty)` — لا خطأ صريح، لكن يُصبح الرصيد 0 |
| رقم الفاتورة | اختياري — يُولَّد تلقائياً إذا غير محدد |
| تاريخ الانتهاء | في صفقات الجاهز فقط، قيمة افتراضية "2028-02-23" |
