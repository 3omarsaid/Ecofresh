# الأدوار والصلاحيات — Nilotic Frost ERP

## نظرة عامة على نظام RBAC

النظام يستخدم **Role-Based Access Control (RBAC)** مُطبَّق في `js/state.js` عبر دالة `ERPState.can(action)`.

---

## الأدوار الخمسة الموجودة فعلاً في الكود

### 1. Admin — مدير النظام والعمليات 👑

```javascript
{ id: "usr-01", name: "م. أحمد محمود", role: "Admin", title: "مدير النظام والعمليات" }
```

| الصلاحية | الحالة |
|---------|-------|
| إنشاء أي عملية تشغيل | ✅ |
| إقفال وإلغاء العمليات | ✅ |
| اعتماد الشحنات | ✅ |
| حذف السجلات | ✅ |
| إدارة المستخدمين | ✅ (UI موجود، غير مربوط بـ backend) |
| قراءة جميع البيانات | ✅ |
| التعديل على البيانات الأساسية | ✅ |

---

### 2. Supervisor — مشرف المحطة والجودة 🛡️

```javascript
{ id: "usr-02", name: "محمد إبراهيم", role: "Supervisor", title: "مشرف عام المحطة والجودة" }
```

| الصلاحية | الحالة |
|---------|-------|
| إنشاء عمليات التشغيل | ✅ |
| إقفال العمليات (LOCK) | ✅ |
| اعتماد وصول الخام (QC Gate) | ✅ |
| حذف العمليات (DELETE_OPERATION) | ❌ محظور |
| الوصول للتقارير المالية | ✅ قراءة فقط |

**منطق الكود:**
```javascript
if (user.role === "Supervisor") {
  return action !== "DELETE_OPERATION";
}
```

---

### 3. Operator — مشغل خط الإنتاج والفرز ⚙️

```javascript
{ id: "usr-03", name: "محمود حسن", role: "Operator", title: "مشغل خط الإنتاج والفرز" }
```

| الصلاحية | الحالة |
|---------|-------|
| إنشاء عمليات تشغيل (CREATE_OPERATION) | ✅ |
| اعتماد الشحنات | ❌ |
| عمليات مالية | ❌ |
| قراءة البيانات الأساسية | ✅ |

**منطق الكود:**
```javascript
if (user.role === "Operator") {
  return action === "CREATE_OPERATION";
}
```

---

### 4. Storekeeper — أمين المخزن 📦

```javascript
{ id: "usr-04", name: "سامح عادل", role: "Storekeeper", title: "أمين مخزن الخام والمستلزمات" }
```

| الصلاحية | الحالة |
|---------|-------|
| تسجيل استلام الخام/المستلزمات (CREATE_OPERATION) | ✅ |
| اعتماد تصدير الشحنة (DISPATCH_SHIPMENT) | ✅ |
| عمليات مالية | ❌ |
| حذف سجلات | ❌ |

**منطق الكود:**
```javascript
if (user.role === "Storekeeper") {
  return action === "CREATE_OPERATION" || action === "DISPATCH_SHIPMENT";
}
```

---

### 5. Viewer — مراقب/مدقق خارجي 👁️

```javascript
{ id: "usr-05", name: "خالد سعيد", role: "Viewer", title: "مراقب / مدقق خارجي (قراءة فقط)" }
```

| الصلاحية | الحالة |
|---------|-------|
| قراءة البيانات | ✅ (كل الشاشات مفتوحة للقراءة) |
| أي عملية إنشاء/تعديل/حذف | ❌ محظور بالكامل |

**منطق الكود:**
```javascript
if (user.role === "Viewer") {
  return false;
}
```

| الإجراء | Admin | Supervisor | Operator | Storekeeper | Viewer |

| العمليات المالية | ✅ | ✅ | ❌ | ❌ | ❌ |
| قراءة التقارير | ✅ | ✅ | ✅ | ✅ | ✅ |

## آلية تبديل المستخدم (User Switcher)

في البروتوتايب، يوجد زر **"تبديل"** في شاشة عمليات التشغيل يتيح تغيير المستخدم النشط مباشرة من الواجهة. هذا للأغراض التجريبية فقط وليس نظام تسجيل دخول حقيقي.

```javascript
// تبديل المستخدم
ERPState.setCurrentUser("usr-02"); // تغيير للـ Supervisor
```

---

## ملاحظات للتطوير

> **[فجوة]** لا يوجد نظام تسجيل دخول (Authentication) في البروتوتايب. RBAC موجود في الكود لكن غير مرتبط بـ session أو JWT. راجع `02-analysis/gaps-and-open-questions.md` للتفاصيل.

> **[فجوة]** الصلاحيات على مستوى المحطة غير مُطبَّقة (مثلاً: Storekeeper محطة النخيل يجب ألا يصل لمخزن محطة السلام).
